# Story 3.3: Product Media Upload

**Status:** completed

**Epic:** 3 - Product Catalog & Inventory
**Story ID:** 3.3
**Story Key:** 3-3-product-media-upload

---

## Story

As a **Merchant**,
I want **to upload images and media for products**,
So that **customers can see what they're buying**.

---

## Acceptance Criteria

1. **AC1 - Image Upload:** Given a product exists, when the Merchant uploads an image, then it is optimized (WebP, max 2000x2000), stored in cloud storage, and associated with the product.

2. **AC2 - Multiple Images:** A product can have multiple images (up to 10). Each image has a position for ordering.

3. **AC3 - Primary Image:** The first image (position 0) is automatically marked as primary. Merchant can change which image is primary.

4. **AC4 - Image Reorder:** Merchant can reorder images via drag-and-drop. The grid updates immediately (optimistic UI).

5. **AC5 - Alt Text:** Merchant can add/edit alt text for each image for accessibility (NFR-A11Y-6).

6. **AC6 - Variant Images:** Variants can have their own specific images linked via `variantId`.

7. **AC7 - Thumbnails:** System auto-generates 400x400 thumbnails for grid displays.

8. **AC8 - File Validation:** Only JPEG, PNG, GIF, WebP allowed. Max file size 10MB. Invalid files show error toast.

9. **AC9 - Delete:** Merchant can delete images. Files are removed from storage and database record deleted.

10. **AC10 - Media IDs:** ProductMedia has CUID IDs with `med_` prefix (e.g., `med_abc123xyz`), automatically generated by the prefixed IDs extension.

## Dev Notes

### Critical Implementation Rules

1. **Prefixed IDs via Extension:** Don't manually generate IDs - PrismaService extension handles `med_` prefix automatically.

2. **Tenant Isolation:** ProductMedia doesn't have direct `storeId` - ALWAYS verify via product relation:
   ```typescript
   const product = await this.prisma.product.findFirst({
     where: { id: productId, storeId, deletedAt: null }
   });
   if (!product) throw new NotFoundException('Product not found');
   ```

3. **Protected Methods Pattern:** Use `protected` (not `private`) for all service methods for @trafi/core extensibility.

4. **Event Emission:** Emit events for all mutations: `media.uploaded`, `media.updated`, `media.deleted`.

5. **Soft Delete Awareness:** When querying products, always check `deletedAt: null`.

6. **REST for Upload:** Use REST endpoint for multipart file upload (tRPC doesn't handle multipart well). Use tRPC for other operations.

### Image Processing Requirements

```typescript
// Optimization settings
const OPTIMIZED_MAX_SIZE = 2000; // max dimension
const THUMBNAIL_SIZE = 400;      // square crop
const WEBP_QUALITY = 85;         // optimized quality
const THUMBNAIL_QUALITY = 80;    // thumbnail quality

// File validation
const MAX_FILE_SIZE = 10 * 1024 * 1024; // 10MB
const ALLOWED_MIMES = ['image/jpeg', 'image/png', 'image/gif', 'image/webp'];
```

### Storage Path Convention

```
{storeId}/products/{productId}/{mediaId}.webp        # Optimized image
{storeId}/products/{productId}/{mediaId}_thumb.webp  # Thumbnail
```

### Data Flow Pattern (from Story 3.2)

```
MediaUploadZone.tsx (Client)
  └─► useUploadMedia() hook
       └─► fetch('/api/v1/products/:id/media') POST FormData
            └─► UploadController.upload()
                 └─► MediaService.upload() (NestJS)
                      └─► StorageService.upload() (S3/R2)

MediaGrid.tsx (Client - for reorder)
  └─► useReorderMedia() hook
       └─► useServerActionMutation(reorderMediaAction)
            └─► reorderMediaAction() (Server Action)
                 └─► trpc.media.reorder.mutate()
                      └─► MediaService.reorder() (NestJS)
```
