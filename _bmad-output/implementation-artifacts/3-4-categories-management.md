# Story 3.4: Categories Management

**Status:** done

**Epic:** 3 - Product Catalog & Inventory
**Story ID:** 3.4
**Story Key:** 3-4-categories-management

---

## Story

As a **Merchant**,
I want **to organize products into hierarchical categories**,
So that **customers can browse products by type**.

---

## Acceptance Criteria

1. **AC1 - Create Category:** Given a Merchant is authenticated, when they create a category with name, slug (optional), and description (optional), then the category is created with a unique slug within the store.

2. **AC2 - Nested Categories:** Categories can have a parent, supporting up to 3 levels of nesting (root -> child -> grandchild). Backend rejects categories deeper than 3 levels.

3. **AC3 - Category Image:** Each category can optionally have an image URL for display purposes.

4. **AC4 - Product Assignment:** Products can be assigned to multiple categories via a many-to-many `ProductCategory` join table.

5. **AC5 - Category Reorder:** Merchant can reorder categories within the same level and move categories between parents via drag-and-drop.

6. **AC6 - Category Slug Uniqueness:** Slugs are unique within the store (scoped to `storeId`). Auto-generated from name if not provided.

7. **AC7 - Category Delete:** Deleting a category removes the category but does NOT delete associated products. Products remain, only the category assignment is removed.

8. **AC8 - Category IDs:** Categories use CUID IDs with `cat_` prefix (e.g., `cat_abc123xyz`), automatically generated by the prefixed IDs extension.

9. **AC9 - Category Tree Query:** Dashboard can query the full category tree (nested structure) efficiently in a single API call.

10. **AC10 - Inline Edit:** Merchant can edit category name inline in the tree view.

## Dev Notes

### Critical Implementation Rules

1. **Prefixed IDs via Extension:** Don't manually generate IDs - PrismaService extension handles `cat_` prefix automatically.

2. **Tenant Isolation:** Category has direct `storeId` - ALWAYS filter by storeId in all queries:
   ```typescript
   const category = await this.prisma.category.findFirst({
     where: { id: categoryId, storeId }
   });
   if (!category) throw new NotFoundException('Category not found');
   ```

3. **Protected Methods Pattern:** Use `protected` (not `private`) for all service methods for @trafi/core extensibility.

4. **Event Emission:** Emit events for all mutations: `category.created`, `category.updated`, `category.deleted`.

5. **Max Depth Validation (3 levels):** Before creating/moving a category, validate depth:
   ```typescript
   protected async validateDepth(parentId: string | null, storeId: string): Promise<number> {
     if (!parentId) return 0; // Root level

     const parent = await this.prisma.category.findFirst({
       where: { id: parentId, storeId }
     });

     if (!parent) throw new NotFoundException('Parent category not found');
     if (parent.depth >= 2) {
       throw new BadRequestException('Maximum category depth is 3 levels');
     }

     return parent.depth + 1;
   }
   ```

6. **Tree Building Pattern:** Store flat, build tree on query:
   ```typescript
   protected buildTree(categories: Category[]): CategoryTreeNode[] {
     const map = new Map<string, CategoryTreeNode>();
     const roots: CategoryTreeNode[] = [];

     // First pass: create nodes
     categories.forEach(cat => {
       map.set(cat.id, { ...cat, children: [] });
     });

     // Second pass: build hierarchy
     categories.forEach(cat => {
       const node = map.get(cat.id)!;
       if (cat.parentId) {
         const parent = map.get(cat.parentId);
         if (parent) parent.children.push(node);
       } else {
         roots.push(node);
       }
     });

     // Sort by position at each level
     const sortByPosition = (nodes: CategoryTreeNode[]) => {
       nodes.sort((a, b) => a.position - b.position);
       nodes.forEach(n => sortByPosition(n.children));
     };
     sortByPosition(roots);

     return roots;
   }
   ```

### Prisma Schema Pattern

```prisma
// apps/api/prisma/schema/category.prisma
model Category {
  id          String    @id @default(cuid())
  storeId     String    @map("store_id")
  name        String    @db.VarChar(100)
  slug        String    @db.VarChar(150)
  description String?   @db.VarChar(500)
  parentId    String?   @map("parent_id")
  imageUrl    String?   @map("image_url") @db.VarChar(2048)
  position    Int       @default(0)
  depth       Int       @default(0)
  createdAt   DateTime  @default(now()) @map("created_at")
  updatedAt   DateTime  @updatedAt @map("updated_at")

  // Relations
  store    Store       @relation(fields: [storeId], references: [id], onDelete: Cascade)
  parent   Category?   @relation("CategoryHierarchy", fields: [parentId], references: [id], onDelete: SetNull)
  children Category[]  @relation("CategoryHierarchy")
  products ProductCategory[]

  @@unique([storeId, slug])
  @@index([storeId])
  @@index([storeId, parentId])
  @@map("categories")
}

// apps/api/prisma/schema/product-category.prisma
model ProductCategory {
  productId  String   @map("product_id")
  categoryId String   @map("category_id")
  position   Int      @default(0)  // Order of product within category
  createdAt  DateTime @default(now()) @map("created_at")

  product  Product  @relation(fields: [productId], references: [id], onDelete: Cascade)
  category Category @relation(fields: [categoryId], references: [id], onDelete: Cascade)

  @@id([productId, categoryId])
  @@index([categoryId])
  @@map("product_categories")
}
```
