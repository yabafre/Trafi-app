# Story 3.5: Collections Management

**Status:** review

**Epic:** 3 - Product Catalog & Inventory
**Story ID:** 3.5
**Story Key:** 3-5-collections-management

---

## Story

As a **Merchant**,
I want **to create curated product collections**,
So that **I can group products for marketing purposes**.

---

## Acceptance Criteria

1. **AC1 - Create Collection:** Given a Merchant is authenticated, when they create a collection with name, slug (optional), description (optional), and image URL (optional), then the collection is created with a unique slug within the store.

2. **AC2 - Collection Visibility:** Collections can be set as visible or hidden (isVisible boolean). Hidden collections are not shown on the storefront but remain accessible in the dashboard.

3. **AC3 - Featured Collections:** Collections can be marked as featured (isFeatured boolean) for homepage or special placement.

4. **AC4 - Product Assignment:** Products can be added to multiple collections via a many-to-many `CollectionProduct` join table.

5. **AC5 - Product Display Order:** Products within a collection have a display order (position field) that can be manually set via drag-and-drop.

6. **AC6 - Collection Slug Uniqueness:** Slugs are unique within the store (scoped to `storeId`). Auto-generated from name if not provided.

7. **AC7 - Collection Delete:** Deleting a collection removes the collection but does NOT delete associated products. Products remain, only the collection assignment is removed.

8. **AC8 - Collection IDs:** Collections use CUID IDs with `col_` prefix (e.g., `col_abc123xyz`), automatically generated by the prefixed IDs extension.

9. **AC9 - Collection List Query:** Dashboard can query all collections with pagination, filtering by visibility and featured status.

10. **AC10 - Collection Detail View:** Dashboard shows collection details with product grid, supporting drag-and-drop reorder.

## Dev Notes

### Critical Implementation Rules

1. **Prefixed IDs via Extension:** Don't manually generate IDs - PrismaService extension handles `col_` prefix automatically. Must add `Collection: 'col'` to `id-prefixes.config.ts`.

2. **Tenant Isolation:** Collection has direct `storeId` - ALWAYS filter by storeId in all queries:
   ```typescript
   const collection = await this.prisma.collection.findFirst({
     where: { id: collectionId, storeId }
   });
   if (!collection) throw new NotFoundException('Collection not found');
   ```

3. **Protected Methods Pattern:** Use `protected` (not `private`) for all service methods for @trafi/core extensibility.

4. **Event Emission:** Emit events for all mutations: `collection.created`, `collection.updated`, `collection.deleted`.

5. **Slug Generation Pattern:**
   ```typescript
   protected generateSlug(name: string): string {
     return name
       .toLowerCase()
       .trim()
       .replace(/[^a-z0-9]+/g, '-')
       .replace(/^-+|-+$/g, '');
   }

   protected async validateSlugUnique(slug: string, storeId: string, excludeId?: string): Promise<void> {
     const existing = await this.prisma.collection.findFirst({
       where: {
         storeId,
         slug,
         ...(excludeId && { id: { not: excludeId } })
       }
     });
     if (existing) {
       throw new BadRequestException('Collection with this slug already exists');
     }
   }
   ```

6. **Product Reorder Pattern:** Use transaction for reordering products:
   ```typescript
   async reorderProducts(storeId: string, collectionId: string, productIds: string[]): Promise<void> {
     const collection = await this.prisma.collection.findFirst({
       where: { id: collectionId, storeId }
     });
     if (!collection) throw new NotFoundException('Collection not found');

     await this.prisma.$transaction(
       productIds.map((productId, index) =>
         this.prisma.collectionProduct.update({
           where: { collectionId_productId: { collectionId, productId } },
           data: { position: index }
         })
       )
     );

     this.eventEmitter.emit('collection.updated', { storeId, collectionId });
   }
   ```

### Prisma Schema Pattern

```prisma
// apps/api/prisma/schema/collection.prisma
model Collection {
  id          String    @id @default(cuid())
  storeId     String    @map("store_id")
  name        String    @db.VarChar(100)
  slug        String    @db.VarChar(150)
  description String?   @db.VarChar(1000)
  imageUrl    String?   @map("image_url") @db.VarChar(2048)
  isVisible   Boolean   @default(true) @map("is_visible")
  isFeatured  Boolean   @default(false) @map("is_featured")
  createdAt   DateTime  @default(now()) @map("created_at")
  updatedAt   DateTime  @updatedAt @map("updated_at")

  // Relations
  store    Store              @relation(fields: [storeId], references: [id], onDelete: Cascade)
  products CollectionProduct[]

  @@unique([storeId, slug])
  @@index([storeId])
  @@index([storeId, isVisible])
  @@index([storeId, isFeatured])
  @@map("collections")
}

// apps/api/prisma/schema/collection-product.prisma
model CollectionProduct {
  collectionId String   @map("collection_id")
  productId    String   @map("product_id")
  position     Int      @default(0)
  createdAt    DateTime @default(now()) @map("created_at")

  collection Collection @relation(fields: [collectionId], references: [id], onDelete: Cascade)
  product    Product    @relation(fields: [productId], references: [id], onDelete: Cascade)

  @@id([collectionId, productId])
  @@index([collectionId])
  @@map("collection_products")
}
```
